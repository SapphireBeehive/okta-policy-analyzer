# TLA+ export

`okta-policy-analyzer export-tla SNAPSHOT -o DIR [--policy NAME] [--assertions FILE] [--run-tlc tla2tools.jar] [--tlc-probes]`
writes one TLA+ module (and TLC `.cfg`) per authentication policy. The module is a *second, independent
backend* for the same semantics: it is generated by translating the z3 formulas the analyzer uses (rule matches,
domain axioms, policy selection) into TLA+ operators, so the two backends cannot drift apart, and TLC's exhaustive
enumeration cross-checks the solver's answers.

## Shape of a module

```tla
VARIABLES user, ctx
UserRecords == [groups: SUBSET Groups, id: UserIds, type: UserTypes, pred: [Preds -> BOOLEAN], attr_user_department: Dom_user_department]
CtxRecords  == [zones: SUBSET Zones, registered: BOOLEAN, managed: BOOLEAN, platform: Platforms, assurances: SUBSET Assurances,
                risk: Risks, authType: AuthTypes, idp: Idps, opaque: [Opaques -> BOOLEAN]]
Axioms      == /\ (ctx.managed => ctx.registered) /\ ("dap_macos_secure" \in ctx.assurances => ctx.platform = "MACOS") /\ ...
Match_0     == ("00g_svc" \in user.groups)
Match_1     == (ctx.registered /\ ctx.managed /\ ("dap_macos_secure" \in ctx.assurances \/ "dap_windows_secure" \in ctx.assurances))
Decision    == IF Match_0 THEN "rul_std_svc_deny" ELSE IF Match_1 THEN "rul_std_managed" ELSE ... ELSE "NO_MATCH"
Strength    == CASE Decision = "rul_std_svc_deny" -> "DENY" [] Decision = "rul_std_managed" -> "TWO_FA_PHISHING_RESISTANT" [] ...
SessionDecision == ...   \* global session policies with fall-through
Init        == user \in UserRecords /\ ctx \in CtxRecords /\ Axioms
Next        == UNCHANGED vars
Spec        == Init /\ [][Next]_vars
SomeRuleDecides == Decision /= "NO_MATCH"
Unreachable_3   == Decision /= "rul_std_contractor_deny"     \* reachability probe: violated iff the rule is reachable
Assert_contractors_denied_off_network == (("00g_contractors" \in user.groups) /\ "nzo_corp" \notin ctx.zones /\ ...) => (~Allowed)
```

Every property is an invariant over the single non-deterministically chosen state, so a TLC violation prints a
concrete world: the TLA+ counterpart of the analyzer's z3 witness.

## State space

The state space is the product of the finite domains of the variables the policy references. The exporter
slices it: only groups, zones and assurance policies mentioned by the policy (and by the axioms and session
policies connected to them) are enumerated; unused dimensions collapse to a single value; enum domains keep only
the values the formulas compare against plus one "other" value; variables forced to a constant by unit axioms
(deleted groups) are substituted. The module header states the estimated number of worlds. On the bundled
fixture the largest policy has about 900k worlds and TLC explores it in ~15 s per property; a real tenant with
hundreds of groups referenced by one policy is out of reach for TLC, which is why z3 is the primary backend.

## Running TLC

TLC stops at the first violated invariant, so the tool runs one TLC process per property (in parallel) and
collects each verdict and witness. `--tlc-probes` adds one reachability probe per rule. Results are compared with
the z3 analyses in `tests/test_tla.py` (set `TLA2TOOLS_JAR` to enable): on the fixture, TLC and z3 agree on the
reachability of every rule and on every assertion.

`java -cp tla2tools.jar tlc2.TLC -workers auto -config Policy_X.cfg Policy_X` runs a module by hand.
